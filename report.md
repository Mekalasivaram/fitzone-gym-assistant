# FitZone Gym Sales Agent — Project Report

**Business problem.** Gym staff repeatedly answer questions about memberships, facilities, and branch details. Visitors also need an easy way to share their fitness goals and request a first visit.

**Solution and working workflow.** FitZone is a fictional gym. This browser prototype supports one end-to-end workflow: a visitor types or uses browser speech to ask a question; the assistant searches a small sample FAQ; it asks for a fitness goal, preferred location, membership interest, and tour time; simple rules estimate lead interest and sentiment; the page creates a conversation summary and saves a tour request in browser storage. The visitor can export an `.ics` calendar request and a `.csv` lead list. The `.ics` file must be imported and staff must confirm the appointment.

**Implementation and architecture.** The interface, JavaScript logic, FAQ, and local storage run in the browser. FAQ retrieval uses keyword matching, not vector search. Conversation history provides session context. Lead score counts how many of four details are present; sentiment uses simple positive/concerned keyword rules. Optional speech input and output use browser speech features. Hindi is offered for speech recognition only; the reply text is English. See `architecture.svg` for current and proposed components.

**Security.** Use fictional details in this demo. Saved records remain in local browser storage on the device and are not encrypted or sent to a server, so this is unsuitable for real customer information. A production system needs consent, encryption in transit and at rest, role-based access, retention rules, audit logs, and secrets stored outside source code.

**Deployment, scale, and cost.** The demo runs as a local static web page. A production version could be deployed to cloud-hosted web servers, with stateless app instances behind a load balancer, managed storage, and a queue for speech/model/CRM tasks. For 100,000 registered users, plan capacity from expected simultaneous calls, then use rate limits, monitoring, backups, and autoscaling. Cost depends on concurrency, call length, speech/model pricing, storage, and hosting region; measure a pilot before estimating spend.

**Commercial feasibility.** A gym could use this service to respond after hours and help staff prioritize interested visitors. Test it at one branch first. Track inquiry-to-tour conversion, missed inquiries, no-shows, and cost per qualified lead. A commercial product could charge gyms by branch, agent usage, or monthly subscription; pricing should follow measured operating costs and value to the gym.

**Limitations and next steps.** This MVP is rules-based, not a generative AI agent. It does not provide true multilingual responses, full RAG, real-time phone calling, a confirmed online calendar booking, or live CRM integration. Next, add an approved knowledge index with retrieval plus an LLM, Hindi response generation and testing, a secure server/database, and calendar/CRM connectors. A production voice system should include consent, escalation to staff, and safeguards for uncertain answers.
